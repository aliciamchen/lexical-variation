# Process a new experiment run

Directory layout and the script table are in `.claude/rules/data-pipeline.md`; `make help` lists the targets. The rules in AGENTS.md "During data collection" apply throughout: the export folders are read-only, nothing that touches the production server runs without the author's confirmation that no game is running, and no full-sample data is committed. This is the procedure.

1. **Choose the export.** Compare `ls experiment/data/` with `data/<name>/runs.txt`. `copy_tajriba.sh` writes a snapshot every five minutes, and Empirica exports are cumulative, so the right one is the newest export in which every game of the session has ended and the exit surveys are in (check `game.csv` status and the players' `exitSurvey` inside the zip); a snapshot taken mid-game or before the surveys arrived has to be replaced later. If the backup loop stopped early, ask the author to run `bash operations/copy_tajriba.sh --once`. Later snapshots identical to a registered one stay unregistered.

2. **Smoke-test it**: `make smoke ZIP=experiment/data/<run>/empirica-export-<run>.zip` runs extract → combine → process (no Vertex AI) → the integrity suite in the throwaway dataset `smoke` without touching any real dataset's `runs.txt`. The block-count checks fail for TEST_MODE games, which is expected; anything else that fails, beyond the known failures in step 5, is a problem with the export to raise before going on. Leave `data/smoke/` and `analysis/derived/smoke/` in place: the next `make smoke` clears them, and the safety hook blocks deleting them.

3. **Extract**: `uv run python analysis/extract_run.py <zip> --dataset <name>`. This unzips into `data/runs/<timestamp>/raw/`, strips the sensitive participant columns, redacts Prolific-id-shaped tokens typed into free text, and registers the timestamp in `data/<name>/runs.txt` (`--no-register` skips that). The pilot is frozen: the script refuses to run without `--dataset` and refuses new runs for `pilots`. When the new export is a later snapshot of the same server as a registered one (the server was not wiped in between), replace the older timestamp in `runs.txt` rather than adding beside it.

4. **Combine**: `make combine DATASET=<name>`. Overlapping snapshots of one server are collapsed to the newest version of each record, and the step reports how many it collapsed; an overlap you did not expect means the wrong export or server. Rehearsal or deploy-check games that ran on the production server go in `data/<name>/exclude_games.txt` (one game id per line, `#` comments) before combining. The step also writes `data/<name>/dropouts.csv` (quiz failures, lobby timeouts, late arrivals).

5. **Process and test.**
   - `make process-no-filter DATASET=<name>` runs preprocessing and the derived metrics on unfiltered utterances. Participants excluded after the fact go in `data/<name>/participant_exclusions.csv` (`playerId,reason`) first.
   - The non-referential filter spends Vertex AI credit. Run `uv run python analysis/filter_nonreferential.py classify --data-dir data/<name> --dry-run`, report the number of new messages and Gemini calls (batches of 30), and get the go-ahead. Then `classify --data-dir data/<name> --yes` (default model `gemini-2.5-flash`, the one every full-sample label came from), and on a `BatchParseError` rerun the remainder with `--batch-size 29` (then 31, 27, 23). `make process DATASET=<name>` then applies the labels and rebuilds the derived tables. Add a line for the new labels to `data/<name>/messages_classified.model.json`. If the filter cannot run, say so: the derived step warns and uses the unfiltered utterances.
   - `make test DATASET=<name>`. Known failures on `full` as of 2026-10-07, none caused by bad data: `test_mixed_groups_are_truly_mixed` (game 9687ZA fell to four players and played its last Phase 2 rounds as unmixed pairs), `test_active_players_have_exit_survey` and `test_exit_survey_understood_field` (six players from the crash-night games 6TKJ8C and 03RTP6 lost their surveys), and `test_the_selection_is_never_committed_before_it_was_made` (two clicks recorded about 170 ms before the choice, one in game 302992 and one in 8E1KHH). Report anything beyond these. If a test fails on a legitimate design feature, propose a fix with the justification and let the author approve it; never edit the data to pass.

6. **Tally**: `make tally DATASET=<name>`. Report the started games per treatment against the target of 15 (intact and partial counts alongside), progress against the cap of 120 started games, and the treatment marked `<- next` (fewest started games), which the next session should run.

7. **Payments**: `make payments DATASET=<name>` (full sample only; the pilot is paid). It reads every export in `runs.txt`, identifies each player by the Prolific id they entered, places them in the study where that id has a submission (by completion code, then by time), and checks each study's submissions with read-only calls. It writes `data/payments/<name>/<date>_<internal name>_<id>/` with the two paste files, `1_main.csv` (bonus, partial, lobby and unsubmitted pay, one line per person) and `2_overtime.csv`, pasted in that order into the study's bulk bonus form, plus `status.csv`; it also finds lobby timeouts who returned without the lobby code, adds the base reward for finishers who returned their submission, and applies the author's corrections in `data/<name>/payment_adjustments.csv` (for example `restore_bonus`). It prints a per-study table and a repeat-participant check (`repeats.csv`), and writes `blocklist_ids.txt`. With the author's go-ahead, `make sync-blocklist DATASET=<name> SYNC_ARGS=--yes` then adds the new names to the `Played the game` participant group that the scheduling surveys block (run it with `SYNC_ARGS=--dry-run` first and report the count); it is the one Prolific write in the tooling and never removes anyone. Report the table (study internal names, counts, amounts, anything owed but not ready, older studies that still owe something, and partial or lobby submissions still awaiting review, which Prolific auto-approves after 21 days), any repeat warning, the number of people on the blocklist, and never participant ids. It pays nobody.

8. **Artifacts and notebooks.** After a session the author expects the published artifacts to be refreshed; memory has each one's URL, builder and rebuild steps. Whether notebooks `02` and `03` and condition-level plots may be rerun is governed by AGENTS.md "During data collection". For the pilot, `SI_pilot.qmd` is frozen with the preregistration; do not run `figures/sync_figures.sh` against `writing/preregistration/`.

9. **Report and stop.** Summarize the export used, games added, the filter status, the test results against the known failures, the tally and the payments table. Do not commit: full-sample data stays local until collection ends, and code changes are committed only when the author asks.
