# Operations tooling

Recruitment, approvals and payment were done by hand on the Prolific website. The tooling in `operations/` only reads, with one exception below, and `operations/procedures.md` is the record of how the 31 sessions were run. There is no production server any more. `make test-ops` runs the operations tests without API access or data.

- **`payments.py`** (`make payments DATASET=full`) works out what each Prolific study still owes. It reads every export zip in `runs.txt` directly, not the processed data; identifies each player by the Prolific id entered on the identifier screen; places them in the study where that id has a submission, by completion code and then by time, so people who reached a game through a link sent by message are paid in the right study; pays anyone with no game-study submission through their latest earlier submission, normally the scheduling survey; and checks each study's submissions and paid bonuses with read-only calls. Output goes to the gitignored `data/payments/<dataset>/`: one folder per study (creation date and internal name) with the paste files `1_main.csv` then `2_overtime.csv` and a `status.csv`, plus `repeats.csv` (anyone in more than one session), `unexplained.csv` (bonuses paid that no row explains; a line one of them may duplicate is held back) and `blocklist_ids.txt`. The rules: a finisher is owed the bonus, plus the base pay if they returned the submission; a removed player their partial pay; a lobby timeout or overflow player (shown the same "no more games" screen) the lobby pay, found by the lobby code on their submission or by the lobby record in the export and paid in exactly one study; an approved submission already carried the base reward; what Prolific records as paid is subtracted. Game-study submissions awaiting review from people owed nothing are listed as `none` and must be returned before Prolific auto-approves them 21 days after submission (the dates are printed). Games in `exclude_games.txt` are paid like any other. `data/<dataset>/payment_adjustments.csv` (`playerId,adjustment,reason`, Empirica ids) holds the author's corrections, such as `restore_bonus` for a removal that was not the player's doing.
- **Reporting payments.** The output covers only the people it can place, so it is a lower bound. Before quoting a total, reconcile it against both ground truths, every export record and every submission on Prolific, and report per-study tables by internal name and study id (every study shares the public name "Group communication game"). Never print `status.csv` rows, participant ids or submission codes, which can be a Prolific id someone typed in. When changing `payments.py`, diff `status.csv` before and after on the real data; the unit tests alone are not enough.
- **`sync_blocklist.py`** (`make sync-blocklist`) is the one Prolific write. It adds everyone on `blocklist_ids.txt` to the participant group `Played the game`, which the scheduling surveys block, never removes anyone, takes effect at once on live surveys, and asks before writing. Ask the author before running it. The list holds everyone who started a game, failed the quiz, or was assigned to a social-first game that never started for them, and everyone from the pilot sessions (read from `experiment/pilot_data/`); lobby timeouts and overflow players of the other three conditions stay eligible, which is why the surveys use the group rather than Prolific's "exclude participants from other studies" filter.
- **`tally.py`** (`make tally`) counts started games per treatment against the cap of 120. **`game_constants.py`** parses completion codes, pay figures and condition names out of `experiment/shared/constants.js` so the tooling cannot drift from the experiment. **`prolific.py`** is the read-only API client (the token is in `.env`; the `/studies/` listing returns each study twice). **`copy_tajriba.sh`** took the five-minute export backups during sessions, and **`final_exports.py`** (`make final-exports`) stages the final export of each server period with every server log in `backups/final_exports/` for the off-site copies. `operations/.sessions/` is leftover state from a retired CLI and means nothing.
