# Data and analysis pipeline

## Datasets

The pipeline is keyed by a dataset name: `--dataset` on a script, else the `DATASET` environment variable, else `full`. `make` passes `DATASET` to every step (`make test DATASET=smoke`). The layout is defined in `pipeline/dataset_paths.py` and mirrored in `analysis/config.R` (`use_dataset()`); change both together. The hand-written inputs sit at the top of `data/<name>/` and everything generated one level down, in a directory per stage: `raw/` (the anonymized raw tables and their `manifest.json`), `tables/` (the analysis-ready tables, with `dropouts.csv` and the filtered utterances and their sidecar), `classifier/` (the message filter's label cache and the author's check), `derived/`, `frames/`, `estimates/` (what the notebooks write) and `cache/` (what they keep between renders). `full` is local and stays so until the RefBank release; the pilot dataset and its SI notebook are at the git tag `pilot-archive`. Everything identifiable (`experiment/data/`, `experiment/pilot_data/`, `data/runs/`, `data/payments/`, `backups/`) is gitignored.

Inputs a dataset directory may hold, each read at the step named:

| File | Read by | Meaning |
|------|---------|---------|
| `runs.txt` | combine | Export timestamps to stack, one per line, `#` comments allowed. Exports are cumulative snapshots of one server, so a later export of the same server replaces an earlier one; `data/full/runs.txt` names the final export of each of its 31 server periods, and `make final-exports` verifies that set |
| `exclude_games.txt` | combine | Game ids dropped with every dependent row: rehearsal games and games with a repeat participant. `make payments` ignores it, so those players are still paid and blocklisted |
| `participant_exclusions.csv` | preprocess | `playerId,reason`, reason required, unknown ids refused. Removes the player's messages from `messages.csv` and both utterance files, so every derived measure excludes them; flags `excluded`/`exclusionReason` on their rows and on the rows of listeners they spoke to in `trials.csv` and `social_guesses.csv`; blanks their `exitSurvey_*` columns in `players.csv` (the answers stay in `raw/`). `responseOpportunity` is left as computed |
| `technical_exclusions.csv` | preprocess (R reports it) | `gameId,playerId,roundId,outcome,reason`, `outcome` one of `referential`, `social`, `both`, reason required: documented technical failures, whose `correct` becomes missing rather than 0 |
| `integrity_exceptions.csv` | integrity suite | `invariant,gameId,playerId,roundId,reason`: the cases where an invariant does not hold. The tests require the cases they find to equal the documented ones, so a new case fails and so does a documented case that disappears. It records data loss and instrumentation races, never analytic choices |
| `payment_adjustments.csv` | `make payments` | See `.claude/rules/operations.md` |

Outputs worth knowing: `raw/manifest.json` (runs combined, games filtered and excluded, dropout count); `tables/dropouts.csv` (player records with no real game: quiz failures, lobby timeouts and overflow arrivals, with `condition` and `tangramSet` from the batch's treatment); and the sidecar `tables/speaker_utterances_filtered.source.json` (below).

## Steps

`make data test models paper`, each verb a group of the finer targets below (`make help` lists them), or `make smoke ZIP=<zip>` to run everything on a throwaway dataset `smoke` (it clears `data/smoke/` itself; leave it afterwards, since the agent hook blocks recursive deletes; the block-count checks fail for TEST_MODE games). The `rebuild-dataset` skill is the procedure for `full`.

- **Extract** (`extract_run.py <zip>`) unzips into `data/runs/<ts>/raw/`, drops `SENSITIVE_COLUMNS` from `player.csv`, redacts 24-hex Prolific-id tokens in every text cell, and registers the timestamp in `runs.txt` unless `--no-register`. It is deterministic.
- **Combine** (`combine_runs.py --dataset <name>`) unions the registered exports on record id, keeping the newest version of each record, drops excluded games, removes player records of games that never started, and writes `raw/` with its manifest and `tables/dropouts.csv`.
- **Process** (`process_data.py`) runs three sub-steps. *Preprocess* (`preprocessing.py`) writes `data/<name>/tables/`, honors the exclusion files, codes the accuracy outcomes and adds the analysis columns (both below), and prints, per column, how many JSON values it could not parse (silence means all parsed). *Filter* (`filter_nonreferential.py`, see `.claude/rules/message-filter.md`) labels speaker messages and writes `speaker_utterances_filtered.csv`; `--skip-filter` falls back to the unfiltered file with a warning. *Derived* (`compute_derived.py`, `--skip-derived` to omit) writes `data/<name>/derived/`: the embeddings, the adjacent, final-window pairwise and block-by-block similarity tables, the pairwise and block tables scored again by content-word Jaccard in the same row order (`*_jaccard.csv`, NaN where a side has no content words), each speaker's Phase 1 to Phase 2 similarity, and the per-description properties (concreteness, word frequency, lexical uniqueness). *Frames* (`build_frames.py`, `--skip-frames` to omit, `make frames` to run alone) writes the model-input frames to `data/<name>/frames/`: `within_group_block_means.csv` and its `_jaccard` twin (one mean per original group, tangram and block over the within-group pairs, the H3b unit), `final_phase_properties.csv` (each speaker's final description of each tangram in each phase with the H3c measures) and `ingroup_advantage.csv` (per listener, Phase 2 accuracy with an in-group speaker minus with an out-group speaker). Every frame keeps all phases and conditions; a model restricts when it is fit.
- **Test** (`make test`) runs the integrity suite on the active dataset, the Python unit tests, and `Rscript analysis/tests/run_all.R`. Besides the game-as-designed invariants it rebuilds both utterance files from `messages.csv` and the classifier labels, recomputes every row of the pairwise, block and adjacent similarity tables from the utterance file and `embeddings.npy`, and reconciles the processed tables with `raw/` and its `manifest.json`, so a derived table that no longer follows from the code fails here.

**Filtered utterances are tied to `messages.csv`.** `apply` writes the sidecar with the sha256 and row count of the `messages.csv` it read. `compute_derived.py` and `config.R` refuse a filtered file whose sidecar is missing or stale, and `preprocessing.py` deletes a stale filtered file when it rewrites `messages.csv`. `dataset_paths.filtered_utterances_status()` is the one check. Never copy a filtered file between datasets.

**Caches are keyed to their inputs.** Both live in `data/<name>/cache/`: `group_specificity.R` stores a hash of the pairwise data beside `gs_results_<speaker structure>.rds` and recomputes when it differs (several minutes), and `bayes_factors.R` names each brms fit in `cache/bayes_factors/` by a hash of data and formula. A rebuild that changes the pairwise tables refits on the next render.

## Definitions that are easy to get wrong

- **`allGroupsPaired`** on both block tables is 1 where every original group has two speakers who have described that tangram by that block, the preregistered start rule for group specificity; it is 0 in the first block of each phase and where a removed or reassigned speaker leaves a group with one describer. Within-minus-between contrasts filter with `specificity_eligible()` (`R/prepare.R`); the descriptive within-versus-between plots use every row.
- **Accuracy denominators** are eligible listener response opportunities, not submitted answers: `hasSpeakerMessage` and `responseOpportunity` on `trials.csv`, and one row per eligible Phase 2 listener in `social_guesses.csv`. A correct on-time answer is 1; an incorrect answer, a timeout and a late arrival are 0. Lateness is `lateClick` and `lateSocialGuess`, set by the server from its deadline snapshot; `preprocessing.py` reapplies `idle.js`'s rule from `clicked_at_deadline` and `social_guess_at_deadline` for answers that arrived after Feedback ended. The outcome is coded once, by `preprocessing.py`, as `correct` (1, 0 or missing) with `onTime` on both tables, and the R helpers read it.
- **Analysis columns.** `trials.csv`, `messages.csv`, both utterance files and `social_guesses.csv` carry `condition`, `block` (the 1-indexed block within the phase, the paper's numbering; `blockNum` is the export's 0-indexed count) and `gameBlock` (counted across the game with each game's own Phase 1 length, so Phase 2 of a 6 + 6 game starts at 7). Figures and models read these and never join the condition or add one to a block themselves.
- **Two clocks.** Participant-clock columns (`selectionRenderedAt`, `tangramSelectedAt`, `clickedAt`, `socialGuessSelectedAt`, `composeStartedAt`) are valid only within one participant, because browser clocks differ by up to minutes; the derived `selectionRt`, `socialGuessRt` and `composeMs` are within-participant differences and safe. Server-clock columns (`selectionStartedAt`, `selectionEndedAt`, `selectionDurationMs` from `stage.csv`, and any raw attribute's `*LastChangedAt`) are comparable across everyone. `tangramSelectedAt` is when the participant chose and is the only response time comparable across conditions; `clickedAt` is when the choice reached the server, which in the social conditions is the submit time.
- **Connection and engagement records** were added during the September 2026 sessions (the connection log from 2026-09-25), so every such field is optional in `preprocessing.py` and an export that predates one must keep processing. An `offline` event is written on reconnect, paired with its `online`; a participant who never came back leaves no record. `players.csv` carries the counts (`tabHidden*`, `offline*`, `resizeCount`, `disconnect*`, `pageLoadCount`, `reloadCount`, the `*Truncated` flags); the event lists stay in `raw/player.csv`; the raw user agent is stripped at extraction. `disconnect*` count only the part of each drop inside the player's game window, which `summarize_connection()` moves onto the participant's clock with `participant_clock_offsets()` (the median of `selectionRenderedAt` minus `selectionStartedAt` over their trials), the one place the pipeline relates the two clocks.
- **Speaker structures** in `group_specificity.R`: `"pair"` (tangram and unordered speaker-pair intercepts) is the preregistered model and what every notebook reports; `"multimembership_pair"`, `"multimembership"` and `"separate"` are for comparison only. The structure is part of the cache key and filename.
- **Convention-formation checks** (`convention_check_data()`) keep all four conditions for description but fit the trend models on `H12_CONDITIONS`; they inform H1 and H2 and gate nothing.
- **Groups.** `originalGroup` persists for the whole game; `currentGroup` changes per trial in mixed Phase 2, where chat names are masked, so `senderName` in `messages.csv` is uninformative there while `senderId` stays valid. The reshuffle guarantees mixing only in rounds where every group is a trio.
- **Repeat participation** is checked by `make payments` (`repeats.csv`), not by the pipeline; a game with a player who had played a full game in an earlier session is excluded whole through `exclude_games.txt`.

## Notebooks and the manuscript

Every notebook sources `config.R`, which sets the dataset's paths and constants and sources every helper in `analysis/R/`; `list2env(load_tables(), envir = globalenv())` loads the tables. The notebooks read the coded outcome and the frames from the tables; `R/prepare.R` only subsets, sets factor levels, centers and adds the reporting flags, and per-game group-specificity estimates come from `game_specificity_table()`, so every notebook reports the same numbers. The R helpers have `stopifnot` tests in `analysis/tests/`, one file per helper.

| Writer | Dataset | Writes |
|--------|---------|--------|
| `checks.qmd`, `primary.qmd`, `secondary.qmd` (`make notebooks`) | `full` (any other dataset gets a warning banner, and its macros are not results) | the inferential macros `writing/manuscript/stats/<checks,primary,secondary>.tex` (the dropout and survey checks are in `checks`); the model estimates in `data/<name>/estimates/` (`gs_by_game.csv` from `primary.qmd`, written with `write_result()` in `R/results.R`, with a manifest); rendered HTML in `_output/` |
| `paper/descriptives.py` (`make descriptives`, after the notebooks) | the same | the descriptive macros `<overview,exploratory,survey>.tex`, from the processed tables, the derived tables, the frames and `gs_by_game.csv` |

The notebooks draw nothing. The article's figures are made in Python from the processed tables and the frames, with `paper/plot_style.py` as the one description of their look: percentile-bootstrap 95% intervals over games with the games as thin lines or points behind the mean, no gridlines, one plot per figure, sentence-case labels, sample sizes written as "16 games" (never "n = 16", which readers take as participants), and never a line for a quantity a condition does not have (`refer_separated` has no out-group speakers). Its `save_fig()` writes into the dataset's figures directory; slide sets go in the gitignored `figures/meetings/<date>/`.

Statistics reach a manuscript only as `\newcommand` macros (letters-only names, `% AUTO-GENERATED` header, never hand-edited), written by R's `write_stats_tex()` or by its Python twin in `paper/stats_tex.py`, which produce the same file; one writer per file, and `check_unique_names()` refuses a name defined in two files. `paper/plot_style.py` is the one description of how the article's figures look (palette, labels, markers, sizes, `save_fig()`), for the Python figures. The `run-analysis` skill is the render procedure, including `BAYES_FACTORS=never|auto|always`. `writing/` is gitignored and versioned on the Overleaf side, so nothing there is committed here. `bash figures/sync_figures.sh writing/manuscript` copies the dataset's figures into the article's project and refuses `writing/preregistration/`, whose figures are frozen with the preregistration.
